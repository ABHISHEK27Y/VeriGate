\begin{center}
    { \LARGE \textbf{Abstract}}
\end{center}
\vspace{1.5cm}
{\large
VeriGate is an organization-aware LLM gateway for internal developer tools, technical
support, and applications across separately configured organizations. Authorized employees
share eligible workspace answers while private responses remain isolated. It addresses repeated
technical requests while avoiding reuse of a nearby but unsuitable recorded answer.
The gateway authenticates a principal, limits reuse to authorized workspace or private
scope, retrieves exact or semantic candidates, and uses an optional answer-aware policy
to assess the stored question, stored answer, and incoming task before a cache hit.
Otherwise it calls the configured provider. Avoiding repeated generation is the intended
cost benefit; gateway computation and storage still incur overhead. Self-verifying denotes this suitability
assessment, not guaranteed factual truth. Exact matching remains the default.
Functional tests, controlled answer labels, and saved MiniLM/RedisSearch HTTP runs
evaluate different parts of the design. In a fresh 25-probe authored HTTP workload,
combined technical guards served 8 of 15 valid opportunities versus 6 of 15 for the
baseline, with no invalid accept among five examples; the improvement missed its
predeclared promotion gate. Mock-provider timings do not establish billed savings
or broad scalability. Independent answer-level review and real-provider validation
remain necessary before production semantic reuse.
}
