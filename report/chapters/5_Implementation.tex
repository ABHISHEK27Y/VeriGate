\section{Gateway Request Path}
The FastAPI routes in \texttt{main.py} authenticate the supplied gateway key and resolve a principal through \texttt{OrganizationDirectory}. The directory selects a permitted scope and provider profile; the registry uses server-owned provider configuration. Rate admission precedes lookup. The request text is classified for no-store or private handling, and volatile requests bypass reuse. The non-streaming handler returns a structured JSON response containing outcome, provider, scope, candidate trace, and stage timings. The streaming handler emits provider events with completion handling. These routes implement a specific gateway contract, not every OpenAI API operation.

\begin{algorithm}[htbp]
\caption{Implemented request decision at the fixed checkpoint}\label{alg:gateway}
\begin{algorithmic}[1]
\State Validate request; authenticate principal and resolve provider registry
\State Apply rate limit; form prompt and resolve authorized scope, route, eligibility
\State Lookup private overlay where applicable; then scoped cache unless bypassed
\If{current exact answer or approved semantic candidate exists}
  \State Recheck principal and return HIT
\EndIf
\State Apply admitted miss/bypass count and request deadline
\State Call configured provider route; require normal completion
\State Classify response; recheck authorization and intended provider
\State Attempt eligible storage in workspace or private scope, subject to TTL/quota
\State Return MISS or BYPASS with provider outcome
\end{algorithmic}
\end{algorithm}

\section{Retrieval and Candidate Selection}
Exact mode hashes the request text and reads the corresponding Redis hash. Semantic mode first tests the same exact key. Otherwise \texttt{Embedder} encodes the incoming question with pinned MiniLM in the measured semantic profile. The RedisSearch backend stores a vector alongside the question, answer, scope, and entry fields and retrieves a scope-filtered top-$k$ shortlist through its HNSW index. The alternative in-process backend keeps a matrix and rebuilds process-local snapshots under locks. In neither backend does a vector score establish that an answer is suitable.

With an answer-policy artifact, each shortlisted candidate passes bounded structural checks, optional named-work and technical/applicability guards, and, if unresolved, an answer assertion NLI score. The assertion contains the stored question, stored answer, and incoming question. The policy records ACCEPT, VERIFY, or REJECT and a reason for each candidate. It may abstain because of a changed qualifier, long input, unavailable model, timeout, or incomplete evidence. Accepted candidates with conflicting answer texts cause a miss. The shortlist and verifier budget are finite; unexamined plausible candidates prevent an unqualified hit. A selected entry is read again and compared before serving, limiting replacement and expiry races.

\section{Credentials and Automatic Scope Resolution}
A gateway key and a provider key serve different purposes. The gateway key identifies the caller and its permissions. A server-configured provider profile identifies the upstream model and references its credential. The credential is resolved on the server when generation is required; it is not fetched from a user's consumer subscription. A HIT avoids that generation call. A MISS consumes the configured provider account's resources, subject to the provider's billing arrangement. VeriGate's request admission counter is separate from token billing.

For normal application traffic, the client omits the optional scope override. The directory selects the application's authorized default workspace. A private-content classification can restrict the request to the employee/application scope, and a secret classification prevents cache use and storage. Response eligibility is checked again before writing because a seemingly general question may receive a private answer. If no shared default is authorized, the request remains private. These decisions are made by the gateway, not by asking the employee to label every prompt.

Shared reuse also requires compatible provider profiles and routes. Two employees in the same organization are not automatically interchangeable across all workspaces or model configurations. These boundaries prevent a convenient shared cache from becoming an unrestricted organization-wide response store.

\section{Organization Example}
The following is an illustrative flow, not a measurement. Employee A asks how to inspect a deployment in a shared technical workspace. A normal provider completion is stored only if the request, response, and authorization permit workspace sharing. Authorized employee C asks a paraphrase in the same workspace. The gateway retrieves A's stored question and answer, checks that C's requested action and environment remain compatible, and may return a HIT after a final entry check. If C asks to \emph{apply} a change while A's answer only explains how to \emph{preview} a Terraform plan, an applicable guard should decline that candidate and use provider fallback. The measured development and lockbox behavior of such action changes is reported separately in Chapter~6; the generality of this example is not established by the illustration.

\section{Providers, Storage, and Concurrency}
The provider registry selects an intended route and supports configured failover and a circuit breaker. The development mock is a deliberate provider choice, not a permanent tail of every live chain. A JSON response is cached only after a nonempty answer and a normal terminal completion; overly long, timed-out, or failed upstream responses produce errors. Streaming has its own first-token and idle deadlines and completion checks. Fallback output from a different intended provider is not written into the intended route's cache.

Redis holds entries, TTL and LRU metadata, admission counts, and, with RedisSearch, the shared vector index. Configured entry quotas restrict a scope; Redis's own memory limit is a separate operational capacity. Singleflight coalesces compatible identical JSON misses within one process; the streaming path does not provide the same coalescing. The in-process vector matrix, model weights, memoized verifier results, and locks are local to a worker. The namespace hashes settings and artifact versions so incompatible cache policies do not silently share old entries. Namespace retirement and TTL are not a complete immediate purge mechanism.

\section{Experimental Task Verifier}
The repository includes an executable task-specific reuse-verifier pipeline that forms an input from stored question, stored answer, and incoming question, separates training and calibration, and loads a manifest with artifact hashes and a threshold. The saved 75-row, five-family source is authored development material. At this checkpoint no trained, independently validated artifact has passed a promotion gate for the selected gateway profile. The pipeline is implemented experimental work; it is not a measured improvement or a replacement for the pinned NLI results in Chapter~6.
