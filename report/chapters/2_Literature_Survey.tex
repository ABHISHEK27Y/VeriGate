\section{Scope of the Comparison}
Semantic answer caching stores a response with a prior request and retrieves it for a
later, related request. The central question is whether the \emph{particular stored answer}
is reusable, not merely whether two question embeddings are close. The systems below
already cover important parts of adaptive and verified caching; VeriGate does not claim
to have invented either idea.

\section{Directly Relevant Systems}
GPTCache is an open-source cache framework with configurable embeddings, vector storage,
similarity evaluation, thresholds, and an optional LLM verifier in post-processing.
It is therefore inaccurate to describe GPTCache as a system that can only use a fixed
threshold or can never verify a candidate. The feature set is documented in its
\url{https://github.com/zilliztech/GPTCache/blob/main/examples/README.md}.

vCache, published as an ICLR paper, learns cache-entry-specific decision boundaries
online and studies user-specified error bounds under its stated model and assumptions.
It compares responses obtained during exploration with cached responses and evaluates
several benchmark distributions. VeriGate's hand-set query threshold has no analogous
guarantee. The paper is available at
\url{https://arxiv.org/html/2502.03771v5}.

Krites studies a static/dynamic cache with a similarity grey zone. It runs an LLM judge
asynchronously after a miss, then promotes approved static responses into the dynamic
cache. Its objective includes preserving critical-path latency and accounting for judge
cost. VeriGate does not implement this policy. The paper is available at
\url{https://arxiv.org/html/2602.13165v2}.

\section{Research Position}
The defensible next question for VeriGate is whether an \emph{answer-aware and cost-aware}
selective verifier can improve the trade-off between valid reuse, incorrect reuse, and
verification latency on a held-out workload. This is a hypothesis, not a current result.
It overlaps with prior verification work, so any eventual contribution must be stated
narrowly: a particular policy and evaluation protocol, with direct comparisons and
negative results included. Query-only NLI is a question-equivalence signal, not proof
that a cached answer is still correct.
