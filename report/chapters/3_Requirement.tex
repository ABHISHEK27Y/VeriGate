\section{Users, Boundary, and Assumptions}
The direct client is an internal developer, support, or organizational application using the gateway's supported chat endpoints. Its VeriGate credential authenticates access and resolves a principal: organization, subject, application, workspaces, permissions, and provider profile. A provider credential is configured on the server for that profile. Authorized employees can reuse eligible workspace answers; private content is scoped to the subject and application. This is an application integration boundary, not an automatic route for consumer ChatGPT or Codex sessions.

The JSON request contract accepts a prompt or supported message structure, an optional cache scope and workspace, bypass, and a supported streaming route. Request-body, prompt, and response limits are configured in the gateway; the implementation is not a universal drop-in OpenAI proxy. Invalid credentials, unauthorized scopes, admission failures, deadlines, and upstream errors produce explicit HTTP errors. Development mock and controlled-evaluation providers are selected configurations. A live provider failure may use configured provider failover; it does not automatically turn into a successful mock answer.

\section{Functional Requirements}
The gateway shall authenticate a principal before cache access; resolve scope and provider compatibility; bypass volatile or ineligible requests; serve current exact entries; rank eligible semantic candidates when semantic mode is enabled; assess the stored answer before a semantic hit when an answer policy is selected; call a configured provider on a miss or bypass; and store only eligible completed responses within the authorized scope. An explicit private request must never broaden into workspace sharing. A workspace request without permission must fail or narrow according to the documented scope decision.

\section{Quality Requirements and Limits}
The desired outcome is fewer upstream calls at acceptable answer suitability and bounded lookup latency. These are goals, not blanket guarantees. A cache lookup consumes Redis, embedding, search, and possibly verifier time; a process-local vectorized scan grows with the number of entries. TTL bounds residence time, not factual freshness. LRU and configured per-scope quotas manage entries; a daily admitted-miss count does not cap billed tokens or money. A rejected candidate is an abstention or policy decision, not a proven false hit. Observed latencies and suitability counts appear only with their measurement boundaries in Chapter~6.
