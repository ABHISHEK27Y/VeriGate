VeriGate demonstrates a working LLM gateway with exact-match caching as its conservative
default and semantic reuse as an opt-in experiment. The gateway implements tenant-aware
storage, rate limiting, provider routing, streaming, and observability. Unit and integration
tests support specific behaviours, but passing tests do not establish that cached answers
are generally safe to reuse.

The current candidate-pair experiment in Chapter~6 is a smoke fixture. It compares query
decision policies on a small set of examples chosen during development. It does not
evaluate answer compatibility, real retrieval, a changing cache, provider correctness,
or measured monetary savings. Its thresholds were not tuned on a separate validation
set. Therefore this report does not claim a formal error guarantee, a production quality
bound, or that adaptive thresholds and verification were invented by this project.

New public pair-proxy experiments now use group-separated partitions, learned and
calibrated accept scores, a filling-cache replay, and a synthetic risk-control exercise.
The QQP-to-PAWS transfer is weak, and strict pair-proxy risk targets lead to reject-all.
Those findings challenge the earlier smoke-set optimism; they still cannot validate
answer reuse. The next research step is independent review of actual cached answers,
followed by a held-out replay and a costed provider comparison. Only then should a
learned or risk-controlled semantic policy be considered for deployment.

Operationally, public deployment still requires production secrets, a real provider,
shared Redis, monitoring, load tests, and a release check for the exact revision being
deployed. The current work is a tested major-project prototype and a basis for rigorous
experimentation, not a completed production service.
