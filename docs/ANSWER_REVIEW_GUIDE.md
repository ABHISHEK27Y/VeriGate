# Reviewing answer reuse

The local review file is `data/answer_review_directional.tsv`. It is generated by
`python -m scripts.audit_answer_labels`, is gitignored, and contains public-dataset
question text. Keep it local and do not commit or upload it.

## Review task

For every row, decide whether the **exact `cached_answer` shown** can answer the
`incoming_query` as written, using only the context shown in that row. Do not infer
that all `stored_aliases` are interchangeable. Use one decision:

- `reuse_ok`: the cached answer is a valid, sufficiently specific answer.
- `reuse_no`: it answers a different fact, conflicts with the expected answer, or
  is too incomplete or broad to answer the incoming question.
- `uncertain`: the row lacks enough context, the question is ambiguous, or valid
  alternatives cannot be established.

Ignore `reuse_ok`, `actual_answer_reference_match`, `reason_code`, `negative_type`,
and any model output while making the decision; these expose the mined label or
diagnostic selection and can bias review. The 200 `diagnostic` rows are intentionally
selected hard cases and must not be used to estimate prevalence. Only the 150
`random` rows are a random sample, and only after independent review and resolution.

## Independent decisions

Give each reviewer a separate copy of the TSV. Reviewers must not see each other's
decisions or discuss rows before submitting. In each copy, fill `review_decision`
with one of the three values above and `review_reason` with a short explanation.
Record the reviewer's identifier in `reviewer_1` or `reviewer_2`, consistently
through that copy. Keep the original copies immutable. Combine decisions only after
both reviewers finish; preserve both decisions, record disagreements as uncertain
until resolved, and document the resolution and resolver. Never edit the source
question or answer to make a row fit a label.

After review, report counts for agreement, disagreement, uncertainty, and resolved
labels by `review_subset`. Keep diagnostic and random results separate. No model
training or answer-quality headline should use unresolved rows.
