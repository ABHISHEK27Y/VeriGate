B.Tech Major Project — LLM Gateway

An LLM gateway with an experimental answer cache.

Exact-prompt reuse is the default. Opt-in answer-aware semantic matching examines a nearby question and its specific cached answer before reuse. It can still accept a wrong answer or reject a valid paraphrase. Each request shows its decision reason.

01

The contribution

A

Adaptive threshold

Match strictness is computed per query from entities, numbers, length and neighbourhood density — not one global constant.

B

Self-verifier

Structural checks filter some changed numbers, roles, scope and tense. The opt-in answer-aware policy evaluates the cached answer with pinned NLI, while uncertain candidates go to the provider.

C

Staleness detection

A keyword rule bypasses some time-sensitive queries. Coverage is incomplete, so other cached answers can become stale.

What the experiments establish
Five overlapping splits of a mined factoid-reference proxy show a risk–coverage trade-off. The conservative token-diff verifier rejects many valid paraphrases; risk selection chose reject-all at 1%, 2% and 5% targets. These results do not measure generated-answer correctness or cloud cost savings. See the repository's experimental results and dataset documentation for run IDs, counts and limitations. The playground uses the configured provider; “mock” means a deterministic local demo answer.
